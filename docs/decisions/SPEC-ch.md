# 历史架构决定

[English](SPEC-en.md)

## 职责与入口

保存已接受决定的上下文、理由和被否决方案。入口为 [决策索引](README-ch.md)，当前系统与模块的可执行边界由 [[architecture]] 及其子树说明。

## 为什么决定记录与当前规格分开

同一记录可以准确描述当时的选择，却因后续实现不再是当前能力清单。保留背景和被否决方案，使 agent 能理解不能重复踩的边界；由当前规格承接仍有效的决定及已核实差异，避免重写历史来制造代码一直遵守决定的假象。[决策索引](README-ch.md) 是这一维护约定的来源。

因此「Accepted」不等于当前实现已满足，「未实现」也必须放回记录发生时的范围。原始决定提供理由，源码提供实现事实，二者不互相冒充。

## 维护边界

ADR 是带时间背景的记录，不是随时覆盖的当前能力清单。0003 的初始状态、0008 的隐私排除、0010 的模型比较等必须放回当时的范围理解，不能据此否认后续实现。

决定确实改变时增加取代它的新 ADR；实现与决定不符时显式记录差异，不先把旧记录改成代码已经满足它。0007 的异常「唯一路径」与当前多个 adapter 直接构造异常的差异由架构规格指出，该差异仍未解决，记录它不等于实现已满足原决定。

本目录的原始 0001—0011 文档保持原位与原编号，作为来源被引用而非逐一注册为侧栏节点。唯一目录节点承载维护规则，不重新定义这些历史决定。

## 证据限制

ADR 的 `Accepted`、Issue 状态和 PoC 文件存在均不证明当前代码或宿主验收。验证链接需要回到对应源码、测试记录与原始运行环境；中文版与英文版不得对同一决定给出不同含义。
